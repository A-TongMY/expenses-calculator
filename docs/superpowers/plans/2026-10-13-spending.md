# Daily Spending Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace check-ins with daily Spending, integrate actuals into Lifestyle calculations, and keep backups on Home without breaking existing functionality.

**Architecture:** Persist one Spending entry list and derive actual totals by category/month. Shared pure calculations feed Expenses, Spending, and Home; a focused Spending controller owns its form and filters. Versioned backup validation upgrades old records without a startup write and preserves conditional remote persistence.

**Tech Stack:** Plain JavaScript ES modules, HTML/CSS, existing SVG charts, Node test runner, Netlify Functions and Blobs.

**Spec:** `docs/superpowers/specs/2026-10-13-spending-design.md`.

## Global Constraints

- Node.js `>=20.12.2`; Windows PowerShell commands and Windows filesystem paths.
- No new product dependencies; use existing chart, icon, form, and persistence helpers.
- Simple existing visual style, short labels, icon actions with accessible names/tooltips, explicit concise errors, and mobile/keyboard support.
- Retain all functionality except the approved removal of check-ins and relocation of normal backups.
- Intentionally discard old check-ins; preserve income, commitments, Lifestyle, houses, and browser migration originals.
- Entries require positive finite amounts up to `MAX_AMOUNT`, required descriptions up to 500 characters, supported real calendar dates, existing category IDs, and active-period membership.
- Limit Spending to 2,000 entries and keep the 2 MiB backup limit.
- Category rename updates labels; block referenced-category deletion and invalidating period edits.
- Actuals replace estimates only for category/month pairs with entries, including future months; no cadence division of actual payments.
- Use conditional Netlify saves, strong reads, and existing failure/conflict/session recovery.
- No real credentials or expense data in verification. No push/deployment without explicit authorization.
- Never change global/repository Git identities. Stage only task-owned paths; commits use command-scoped `user.name=A-TongMY` and `user.email=45504842+A-TongMY@users.noreply.github.com`, with the Copilot coauthor trailer.

- Execution stays on already-authorized `main` unless the user requests a different branch/worktree.

## Task 1: Build the pure Spending domain

**Files:** Modify `rules.js`, `calc.js`, `format.js`; create `spending.js`, `test/spending.test.js`; extend `test/calc.test.js`.

**Interfaces:**

- `isDate(value)` accepts real `YYYY-MM-DD` dates in 1900..9999.
- `MAX_DESCRIPTION_LENGTH = 500`; `isValidSpending(entry, lifestyle)` validates all fields and category/period membership.
- `spendingTotals(spending = [], month)` returns a `Map<categoryId, roundedAmount>` for that month.
- `saveSpendingEntry(state, entry)` returns a new state, replacing a matching ID or appending, and throws a concise validation/limit error without changing input.
- `deleteSpendingEntry(state, id)` returns new state without that ID, rejecting unknown IDs.
- `assertLifestyleChangeAllowed(state, nextLifestyle)` throws if referenced IDs disappear or proposed periods invalidate entries; renames/estimate edits remain allowed.
- `spendingReport(state, month, categoryId = null)` returns `{ month, entries, total, count, average, categories }`; `categories` is `{ id, name, amount }[]` sorted amount descending, then name.
- `spendingComparisons(state)` returns monthly/category records `{ month, itemId, name, low, high, actual }` from recorded pairs and current estimates.
- `currentDate()` and `dateLabel(date)` use local calendar components, not UTC date truncation.

In `calc.js`, aggregate entries once per requested month and round only the final category sums:

```js
export function spendingTotals(spending = [], month) {
  const totals = new Map();
  for (const entry of spending) {
    if (entry.date.slice(0, 7) !== month) continue;
    totals.set(entry.categoryId, (totals.get(entry.categoryId) ?? 0) + entry.amount);
  }
  return new Map([...totals].map(([id, amount]) => [id, roundToSen(amount)]));
}
```

The domain module imports existing math/validation rather than introducing a
`calc.js` -> `spending.js` -> `calc.js` dependency. Use stable IDs, immutable arrays,
and explicit errors. Report rows join categories by ID. Compute averages from the
selected month's real calendar length. Sort dates descending with deterministic
saved-list order for ties; never invent timestamps.
